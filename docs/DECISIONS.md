# Decisiones de diseño

Complementa `docs/SPEC.md`. Cada decisión resuelve un hueco o una contradicción de la especificación.

## Hito 1 (2026-09-27)

| Tema                    | Decisión                                                                                                                                                     |
| ----------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| Ids                     | La app genera `prefijo_` + cuid2 (`src/lib/ids.ts`); el esquema no usa `@default(cuid())`. Prefijos: `biz`, `kb`, `conv`, `msg`, `hof`, `hev`, `usr`, `ses`. |
| Sesiones del panel      | Tabla `Session` (token aleatorio en cookie httpOnly; en la base solo su hash). Revocable en logout.                                                          |
| Bloqueo de login        | `User.failedLoginCount` y `User.lockedUntil` (15 min tras 5 intentos fallidos).                                                                              |
| Saludo y sugerencias    | Campos editables `Business.greeting` y `Business.suggestions` (máx. 3), devueltos por `/widget/config`.                                                      |
| "Probar" del panel      | `Conversation.isPreview = true`: no envía correos y no cuenta en métricas ni en la bandeja de derivaciones.                                                  |
| Límite por IP           | En memoria (una sola instancia en el MVP).                                                                                                                   |
| Tope diario del negocio | Se cuenta en la base; el "día" se evalúa en el `timezone` del negocio.                                                                                       |
| Índices extra           | `Handoff(conversationId, status)` para la derivación pendiente única; `HandoffEvent(handoffId, createdAt)`.                                                  |
| Versiones               | TypeScript 6.0 (typescript-eslint aún no soporta 7), Prisma 7 estable con `@prisma/adapter-pg` (8 está en RC), pnpm 10.                                      |
| Pruebas de la API       | Base separada `puente_test` (`TEST_DATABASE_URL`); vitest se niega a correr si coincide con `DATABASE_URL`.                                                  |
| Puertos locales         | postgres 5433, mailpit SMTP 1026 / web 8026, para no chocar con otros proyectos.                                                                             |
| docker compose          | Por ahora solo postgres y mailpit; api y panel se agregan cuando existan (hitos 2 y 4).                                                                      |

## Hito 2 (2026-09-27)

| Tema                    | Decisión                                                                                                                                                                                                                                                      |
| ----------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Salida de la IA         | Salidas estructuradas (`output_config.format` con JSON Schema) + validación Zod (`LlmOutputSchema`) + extracción tolerante como red de seguridad. `stop_reason` distinto de `end_turn` (corte o rechazo) se trata como salida inválida → `TECHNICAL_FAILURE`. |
| Reintentos de la IA     | Reintentos del SDK apagados. Un solo reintento propio ante error de red o 5xx; nunca ante timeout ni 4xx. Un único plazo total de `LLM_TIMEOUT_MS` para ambos intentos.                                                                                       |
| Caché de prompts        | Se marca el prompt del sistema con `cache_control`, pero en Haiku 4.5 solo se cachea desde 4096 tokens: con bases chicas no hay ahorro (tampoco costo extra).                                                                                                 |
| Derivación existente    | Se conserva el motivo original. Resumen y mensaje de WhatsApp se reemplazan solo si la nueva derivación viene de la IA; las de reglas/servidor solo registran el evento `updated`.                                                                            |
| Correos                 | Al crear un caso y al pedir contacto. Las actualizaciones no envían correo. Las conversaciones de prueba (`isPreview`) nunca envían.                                                                                                                          |
| Concurrencia            | La fila de la conversación se bloquea (`SELECT … FOR UPDATE`) al crear/actualizar la derivación: nunca hay dos pendientes.                                                                                                                                    |
| Límite por conversación | El mensaje se guarda y se cuenta siempre; desde el mensaje `max + 1` se deriva con `LIMIT` sin llamar a la IA.                                                                                                                                                |
| CORS                    | El preflight responde a cualquier origen (no trae la clave); la respuesta real solo lleva `Access-Control-Allow-Origin` si el origen está autorizado para esa clave.                                                                                          |
| Contacto                | El pedido de contacto exige `consent: true` además del teléfono.                                                                                                                                                                                              |
| Mensaje de WhatsApp     | `waMessage` se guarda sin el código; `waUrl` lleva el texto + `(Caso DER-XXXX)`. Se eliminan enlaces a nuestras propias apps.                                                                                                                                 |
| Pruebas de correo       | `mailpit.test.ts` envía por SMTP real y lo busca en la API de mailpit (`MAILPIT_URL`); el CI levanta mailpit.                                                                                                                                                 |

## Hito 3 (2026-09-27)

| Tema                       | Decisión                                                                                                                                                                                                                          |
| -------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| URL de la API en el widget | Se fija al compilar (`PUBLIC_API_URL` → `__PUENTE_API_URL__`); el atributo `data-api` del `<script>` la reemplaza (demo y pruebas).                                                                                               |
| Recarga de página          | Además de los ids, `localStorage` guarda los últimos 50 elementos de la charla (mensajes y tarjeta de derivación) por clave de negocio. Todo acceso va en try/catch; sin storage el widget funciona en memoria.                   |
| Contratos                  | El widget importa solo tipos de `@puente/shared`: el bundle no incluye zod. Seguridad: todo texto va por `textContent`; solo se enlazan URLs `https://wa.me/…`.                                                                   |
| Widget no autorizado       | Si `/widget/config` falla (clave o dominio), el widget no se muestra y deja un aviso en la consola.                                                                                                                               |
| Tamaño                     | `pnpm build` falla si `dist/v1.js` supera 40 KB gzip (hoy ~6 KB).                                                                                                                                                                 |
| Semilla                    | Fuera de producción, Óptica Mirador usa la clave fija `pk_demo_opticamirador` (la demo funciona sin copiar claves).                                                                                                               |
| Pruebas e2e                | Playwright sobre `demo/index.html?bundle=1` (el bundle real). La API corre con `test/e2e-server.ts`: rutas y base reales (`puente_e2e`), IA falsa por palabras clave. `wa.me` se intercepta en el navegador. Job propio en el CI. |

## Hito 4 (2026-09-27)

| Tema               | Decisión                                                                                                                                                                                                                                                                            |
| ------------------ | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Topología          | **Mismo origen, un solo servidor**: el dominio de Puente sirve el panel (`/`), la API (`/v1`) y el widget. En desarrollo Vite hace proxy de `/v1`; en producción lo hará el servidor (Hito 6). El sitio del comercio solo pega el `<script>` del widget (CORS por negocio, Hito 2). |
| Sesión             | Cookie `puente_session` httpOnly, Secure, SameSite=Lax, 7 días. En la base, HMAC-SHA256 del token con `SESSION_SECRET`. Logout la borra.                                                                                                                                            |
| Login              | argon2id; 5 fallos → bloqueo 15 min (429 `too_many_attempts`); correos inexistentes verifican contra un hash señuelo (mismo tiempo, mismo error). Límite por IP también en el login.                                                                                                |
| CSRF               | Además de SameSite=Lax, toda petición que modifica datos con `Origin` debe venir de `PANEL_URL`.                                                                                                                                                                                    |
| Roles              | ADMIN: todo. AGENT: resumen, derivaciones, casos, probar e instalación; ve la configuración en solo lectura; no ve la base de conocimiento.                                                                                                                                         |
| Tasa de resolución | Por conversación: conversaciones con al menos un mensaje del cliente y sin derivación / conversaciones con mensajes. Período por días locales del negocio (por defecto, últimos 30).                                                                                                |
| Reabrir un caso    | Si la conversación ya tiene otra derivación pendiente, responde 409 `conflict` (se mantiene la regla de una sola pendiente).                                                                                                                                                        |
| "Probar"           | Reusa el componente del widget en modo `inline` contra `/admin/preview-chat`. "Que me contacten" y WhatsApp no registran nada. Las conversaciones de prueba nunca continúan una real, ni al revés.                                                                                  |
| Usuarios           | Se crean con la semilla; no hay pantalla de gestión de usuarios (fuera de la especificación).                                                                                                                                                                                       |
| Horario compartido | `isInHours`/`startOfLocalDay` viven en `@puente/shared` (panel y API usan la misma lógica).                                                                                                                                                                                         |

## Hito 5 (2026-09-27)

| Tema                   | Decisión                                                                                                                                                                                                                                                        |
| ---------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Retención              | Se borran las conversaciones con `lastMessageAt` anterior a `RETENTION_DAYS`, con sus mensajes, derivaciones (también las pendientes) y eventos, más las sesiones vencidas. Corre al iniciar la API y cada 24 h; también `pnpm --filter @puente/api retention`. |
| Tipo de falla de la IA | `Message.llmError` (`timeout` / `api_error` / `invalid_output`) en la respuesta de derivación. Un plazo vencido siempre cuenta como `timeout`.                                                                                                                  |
| Alerta                 | Cada 5 min: fallas / (respuestas con IA + fallas) en la última hora, en todos los negocios. Alerta si supera 5 % con al menos 20 intentos; log de error y correo a `ALERT_EMAIL`, como mucho una vez por hora.                                                  |
| Costo                  | Estimado con `LLM_PRICE_INPUT_PER_MTOK` / `LLM_PRICE_OUTPUT_PER_MTOK` (por defecto Haiku 4.5: 1 y 5 USD). Los tokens de caché se cuentan como entrada normal.                                                                                                   |
| Logs de errores        | Los errores inesperados se registran con tipo, código y pila, sin el mensaje.                                                                                                                                                                                   |
| Dependencias           | `pnpm audit` (nivel alto) en el CI; `overrides` para dependencias del CLI de Prisma con avisos.                                                                                                                                                                 |
| Checklist              | `docs/SECURITY.md`.                                                                                                                                                                                                                                             |
